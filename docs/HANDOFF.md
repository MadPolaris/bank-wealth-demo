# 运行与生成侧移交：银行财富真源预览

本批只处理 `bank-wealth-demo`。没有修改 Saga/Monarch、JS/BC 编译器、生成器、共享应用或运行服务。另一位 agent 的 money/Fab/组合验收不自动扩展到银行财富业务。

## 已有接口与不变领地

`tree/sagas/`、`tree/pipelines/`、三个根绑定 JSON、`compiled/` 和两份 Scala 样例保持原字节；保护哈希记录在 `BASELINE.json`。当前严格编译验收只证明声明被当前编译器接纳，不证明绑定中的 fixture 类存在或应用可运行。

本批新增体验与上下文信息使用已有 note 的 JSON `payload.info.artifact` 承载，状态为 `demo-proposal`。没有新增公共 UI Schema，没有改变公共 context/subdomain target 索引，也没有建立多上下文代码生成支持。图投影属于本仓库知识预览，不是业务运行时 CQRS 投影。

## 下一阶段必须解决的业务桥接

| 主题 | 需要的真源/运行能力 | 不能采用的捷径 |
|---|---|---|
| 外部银行 | 授权、真实通道能力、幂等身份、结果未知、对账与退汇契约 | 本地 ExternalTransferOrder 有 prepare/commit 字段不证明外部银行支持 TCC |
| 基金付款 | 明确现金收款/结算账户、账务事实与订单支付标记的对应 | 把 FundOrder 的 PAYMENT_SETTLED 标记当作已经证明资金守恒 |
| 基金公司/TA | 用户允许模拟；实现有状态、可控时钟和明确回执关联的模拟器 | 始终成功的 mock 不能覆盖等待、拒绝、未知或冲突回执 |
| 份额确认 | 子计划终态→RecordTAShareConfirmation 的持久化桥接、接收方去重和关联校验 | Pipeline 输出存在不等于订单/持仓事件已经落盘 |
| 支付后退款 | 新退款身份、授权来源、资金来源/目标、受理/完成/失败事实 | 已提交付款后的退款不能调用 ReleaseReservedFunds，也不是付款 Saga Prepare 的补偿 |
| 定投 | 计划配置→期次输入一致性、已触发/待结束/终态记录、乱序和冲突处理 | 调度重复空成功不代表不同参数同身份和终态覆盖均已处理 |
| 连续失败暂停 | 哪些失败计数、连续顺序、成功清零、未知结果处理、第三次暂停条件 | 失败事件无条件调用 PauseSipPlan 不等于连续三次失败暂停 |
| 领域→体验 | 用户状态映射、读模型新鲜度、授权/资源归属、恢复动作及反馈 | parameter.origin/stateGates/Pipeline stage 不能机械生成可信 UI |

## 已修复声明的执法边界

- 新增请求字段的 `writtenBy` 与 `event.*` fold，是可回放状态声明；本批不执行 Akka 事件回放测试。
- legacy `statusTransition` 由当前通用工具保真承载，本地检查其状态、规则/错误码与位置。实际生成与运行强制执行仍需下一阶段验收。
- **已发现的生成侧阻碍**：当前 `metarch-truthsrc/generators/run-all.mjs` 将既有 legacy guards 与结构化 guards 分组再合并；这可能让状态门禁先于声明在前的幂等空成功守卫执行。需在生成器侧保持原声明顺序并加混合 guard 回归；本批不修改该路径。
- TA 完成状态门禁可以拒绝不合时序的确认，但第二次确认被拒绝不等于适配器已经实现幂等回执处理。
- 当前 guard 的 `money-positive` 只表达正数。真实基金最低起购额、费用、业务日历和精度/舍入需要独立裁定并有支持的契约。
- 账户示例以 AccountId 标识单一账户，accountBalance 是该账户内的币种余额；开户、归属、冻结账户/销户及监管要求不在当前实现中。

## 最小联合验收路径

先打通本行账户申购：

1. 请求与授权→正确的资金/订单协作。
2. 模拟 TA 受理；延迟与结果未知时保持安全状态。
3. 确认份额→持久化订单/持仓；相同/冲突回执分别验收。
4. TA 拒绝→独立退款业务→现金/订单终态与用户反馈。
5. 重启与恢复→无重复财务效果→代码锚可定位到正确的真源规则。

资金、TA 和用户状态须用可观察事实验收。只有图或源码生成成功，不应称端到端业务通过。

## 工具兼容性

本地 Node 工具通过 `TRUTHSRC_ROOT`（默认 `../metarch-truthsrc`）读取纯库 API；缺少该 sibling 时显式失败，不下载或静默切换实现。验证记录工具 HEAD 和导入闭包/Schema 指纹，运行中来源改变会拒绝认证该轮结果。

未来若升级公共 contract 或生成器，先重新评估新增 payload 的兼容性与当前保护声明。不要把本批的 proposal carrier 升格为公共执行 DSL 而没有 schema、校验器、生成器与回锚消费者。
